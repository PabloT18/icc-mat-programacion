Generación de diapositivas – Programación Aplicada

Genera una presentación académica universitaria utilizando exclusivamente el contenido de las siguientes fuentes:

  • 2.1.-algoritmos

1. Objetivo

Crear diapositivas para la asignatura Programación, dirigidas a estudiantes universitarios de la carrera de Computación.

La presentación debe explicar los fundamentos conceptuales y teóricos de los tres temas, con ejemplos de código que faciliten la comprensión de los conceptos.

Debe funcionar como material de apoyo para la explicación del docente durante la clase, no como una guía de laboratorio.

2. Alcance del contenido

Desarrollar los siguientes temas respetando el orden de las fuentes:

Algoritmos conceptos , variables represetnaciones diagramas de flujo; concpeto , graficos; Decisiones: acción opcional, alternativas y encadenamiento;Prueba de escritorio y revisión de caminos

Utiliza estos apartados como orientación temática, pero prioriza los conceptos y el alcance real de las fuentes proporcionadas. Conceptos y graficas como explcia y se compaort acada metodo especialemente para los ejecrios de dejmostracion

3. Restricciones de contenido

Incluir:

  • Definiciones técnicas claras y precisas.
  • Explicaciones conceptuales breves.
  • Comparaciones entre conceptos cuando aporten claridad.
  • Diagramas conceptuales, esquemas y representaciones visuales.
  • Consideraciones técnicas y errores conceptuales frecuentes.

Excluir completamente:

  • Proyecto acumulativo
  • Prácticas de laboratorio.
    1. PC2.1 · Diseñar, justificar y probar diagramas
  • Ejercicios propuestos para estudiantes.
  • Actividades de evaluación.
  • Evidencias de aprendizaje.
  • Instrucciones para desarrollar proyectos.
  • Rúbricas y entregables.

Los ejemplos de código pueden proceder de las secciones de demostración de las fuentes, pero deben presentarse únicamente como ilustraciones de conceptos teóricos, sin instrucciones de ejecución ni desarrollo de actividades.

4. Diseño visual

Utilizar un estilo académico, moderno, minimalista y profesional.

Paleta de colores sugerida:

  • Fondo principal: blanco #FFFFFF.
  • Azul principal: #003772.
  • Azul secundario: #07508E.
  • Amarillo de acento: #FCC000.
  • Texto principal: gris oscuro #1F2937.

El fondo de todas las diapositivas debe ser blanco., sin cuadriculas de fongro tipo grids

Utilizar el azul principal para títulos y encabezados, el azul secundario para elementos gráficos y el amarillo para destacar conceptos o detalles importantes.

Evitar fondos completos de colores intensos, degradados excesivos y elementos decorativos innecesarios.

Presentación del código

Los fragmentos de código Python deben utilizar un diseño visual propio de un editor de programación moderno:

  • Fuente monoespaciada.
  • Resaltado de sintaxis coherente con Java.
  • Palabras reservadas, tipos, cadenas, números y comentarios visualmente diferenciados.
  • Fondo de código oscuro, preferentemente #1E1E1E o #0D1117.
  • Contraste adecuado y tamaño de letra legible.
  • Indentación correcta.
  • Código breve y centrado en un único concepto.

Se permite utilizar paneles oscuros exclusivamente para los fragmentos de código, manteniendo blanco el fondo general de la diapositiva.

No representar código mediante imágenes decorativas si afecta su legibilidad.

5. Organización de las diapositivas

  • Iniciar con una portada que indique la asignatura y los temas abordados.
  • Organizar el contenido en tres secciones, siguiendo el orden de las fuentes.
  • Introducir cada concepto antes de presentar su ejemplo.
  • Dedicar preferentemente una diapositiva a cada concepto importante.
  • Cuando corresponda, utilizar una diapositiva para explicar el concepto y otra para mostrar un ejemplo representativo.
  • Incluir tablas comparativas únicamente cuando mejoren la comprensión.
  • Incorporar diagramas sencillos para explicar relaciones entre tipos, métodos y estructuras.
  • Finalizar con una síntesis de los principales conceptos técnicos.

No agregar secciones de prácticas, ejercicios, actividades ni proyectos.

6. Criterios de calidad

  • Mantener precisión técnica y terminología
