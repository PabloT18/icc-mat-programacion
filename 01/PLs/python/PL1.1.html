PL1.1 · Reglas de acceso y tablas de verdad

Objetivos prácticos

  • Formalizar una política mediante expresiones booleanas.
  • Verificar equivalencias y explicar casos límite.

Contexto

Una sala permite ingresar cuando existe credencial vigente y reserva, o autorización del responsable. Si existe bloqueo de seguridad, denegar siempre. Diseñar y comprobar la política con cuatro variables booleanas.

Recursos y tiempo

Computador, Python, editor, terminal y Git. Utilizar bibliotecas estándar. Tiempo estimado docente: 2 horas. Esta estimación no modifica las horas oficiales del programa.

Instrucciones y restricciones

  • Usar únicamente valores booleanos para las cuatro condiciones.
  • Entregar tabla manual de 16 filas y expresión original y simplificada.
  • Usar Python para contrastar cada fila. Se permite escribir casos explícitos sin ciclos.
  • No conectar la solución con servicios de acceso reales.

Actividades por fases

1. Analizar

Definir proposiciones, prioridad del bloqueo y salida. Escribir dos casos que suelen confundirse.

Registrar un commit funcional: feat(pl1.1): fase-1-descripcion. Sustituir descripción por el cambio realizado y conservar el hash real.

2. Diseñar

Construir tabla completa y una expresión equivalente utilizando De Morgan para la denegación.

Registrar un commit funcional: feat(pl1.1): fase-2-descripcion. Sustituir descripción por el cambio realizado y conservar el hash real.

3. Implementar

Codificar la expresión en Python y contrastar las 16 filas con la tabla manual.

Registrar un commit funcional: feat(pl1.1): fase-3-descripcion. Sustituir descripción por el cambio realizado y conservar el hash real.

4. Verificar y defender

Explicar discrepancias, corregir y demostrar el efecto de cambiar la regla de autorización.

Registrar un commit funcional: feat(pl1.1): fase-4-descripcion. Sustituir descripción por el cambio realizado y conservar el hash real.

Resultados que registrar

Construir una tabla con caso, entrada, resultado esperado, resultado real y evidencia. Anotar el comando, la versión y el hash del commit entregado. Registrar limitaciones y pruebas que no se hayan completado.

Defensa

  • Explicar por qué el bloqueo afecta a toda la expresión.
  • Negar la autorización sin cambiar el significado de las otras condiciones.
  • Justificar una equivalencia con todas las filas.

Explicar el código del commit entregado, ejecutar una prueba nueva y realizar una modificación pequeña. Declarar herramientas utilizadas y comprobar personalmente sus resultados.

Conclusiones

Redactar tres conclusiones relacionadas con casos realmente ejecutados: corrección de la regla, decisión de diseño y límite observado.

Recomendaciones

Proponer una mejora concreta, justificarla con una prueba y explicar qué partes de la solución cambiarían.
