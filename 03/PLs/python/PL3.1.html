PL3.1 · Analizador de mediciones por consola

Objetivos prácticos

  • Integrar entrada, conversión, decisiones y ciclos.
  • Validar datos y producir un resumen sin almacenar todas las observaciones.

Contexto

Crear una aplicación de consola para procesar mediciones enteras entre -50 y 150 hasta recibir FIN. Mostrar cantidad, mínimo, máximo, promedio y cantidad fuera del intervalo de referencia [0,100].

Recursos y tiempo

Computador, Python, editor, terminal y Git. Utilizar bibliotecas estándar. Tiempo estimado docente: 4 horas. Esta estimación no modifica las horas oficiales del programa.

Instrucciones y restricciones

  • Aceptar FIN sin distinguir mayúsculas y quitando espacios externos.
  • Rechazar formato no entero y valores fuera de [-50,150].
  • No usar listas ni funciones propias todavía.
  • Mostrar Sin datos si no hay mediciones válidas y dos decimales en el promedio.

Actividades por fases

1. Contrato y ejemplos

Acordar formato de cada mensaje y calcular manualmente al menos cuatro casos.

Registrar un commit funcional: feat(pl3.1): fase-1-descripcion. Sustituir descripción por el cambio realizado y conservar el hash real.

2. Lectura y validación

Construir el ciclo, recuperar errores de conversión y excluir FIN de los cálculos.

Registrar un commit funcional: feat(pl3.1): fase-2-descripcion. Sustituir descripción por el cambio realizado y conservar el hash real.

3. Resumen

Actualizar acumuladores y extremos solo para valores válidos.

Registrar un commit funcional: feat(pl3.1): fase-3-descripcion. Sustituir descripción por el cambio realizado y conservar el hash real.

4. Verificación

Ejecutar entradas desde archivos, comparar stdout y documentar correcciones.

Registrar un commit funcional: feat(pl3.1): fase-4-descripcion. Sustituir descripción por el cambio realizado y conservar el hash real.

Resultados que registrar

Construir una tabla con caso, entrada, resultado esperado, resultado real y evidencia. Anotar el comando, la versión y el hash del commit entregado. Registrar limitaciones y pruebas que no se hayan completado.

Defensa

  • Explicar por qué mínimo no se inicializa en cero.
  • Cambiar el intervalo de referencia sin alterar el de validación.
  • Demostrar una entrada inválida en vivo.

Explicar el código del commit entregado, ejecutar una prueba nueva y realizar una modificación pequeña. Declarar herramientas utilizadas y comprobar personalmente sus resultados.

Conclusiones

Redactar tres conclusiones relacionadas con casos realmente ejecutados: corrección de la regla, decisión de diseño y límite observado.

Recomendaciones

Proponer una mejora concreta, justificarla con una prueba y explicar qué partes de la solución cambiarían.
